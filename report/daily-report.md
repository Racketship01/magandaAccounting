📐 Task Completed
1️⃣ **localStorage-Toasted-IDs Set (Fix: Re-Toasting Same Unread)**
• **New helpers**: `loadToastedIds()` and `saveToastedIds()` read/write a JSON array under the key `"app-notifications-toasted-ids"`, guarded by `typeof window !== "undefined"` so they safely no-op during SSR / Nitro pre-render. Both helpers wrap their body in `try/catch` to survive localStorage unavailability (private mode, quota hit) and serialization failures without throwing.
• **Size cap**: `saveToastedIds` always stores `[...set].slice(-200)` — effectively an LRU cap of the 200 most-recently-toasted IDs, since each new toast appends and we keep the tail. Keeps localStorage usage under ~4 KB worst-case (UUIDs are 36 bytes → 200 × 36 + JSON brackets = ~7 KB on disk; still comfortably under the 5 MB site quota).
• **New-fetch toast gate**: On non-initial fetches (the `hasFetchedInitial.value === true` branch), we still compute `newIds` via `currentUnreadIds − prevUnreadIds`, but now we **further filter** against `loadToastedIds()` to get `toastableIds` = truly-new-and-never-before-toasted. Only `toastableIds` can trigger a `toast.add(...)`.
• **Post-toast persistence**: After firing `toast.add()` for the newest, we do `toastableIds.forEach(id => toastedIds.add(id))` then `saveToastedIds(toastedIds)` — even IDs that weren't the "picked toast winner" this tick are marked done, because the user won't want them as toasts on the next tick either.
• **Initial-fetch hydrate**: On the very first load (`hasFetchedInitial.value === false`), we load all current-unread IDs into `toastedIds` and save — so that very-first-load unreads don't get a spam of old toasts when the user logs in after weeks away.

2️⃣ **SSE Error Single-Flight Flag (Fix: Error Toast Spam)**
• **New reactive flag**: `streamErrorShown = useState<boolean>("app-notifications-stream-error-shown", () => false)` — scoped per `useState` key so multiple component consumers share the flag, preventing double-tracks.
• **onmessage clears the flag**: Every successful SSE `onmessage` (first line inside the try) sets `streamErrorShown.value = false;`, so on next error we can surface the error again — we only suppress _consecutive_ errors without an intervening success in between.
• **onerror gated with if**: Previously `eventSource.onerror` always called `toast.add(...)`. Now it's `if (!streamErrorShown.value) { streamErrorShown.value = true; toast.add(...) }` — so the error surface-once per reconnect-cycle, not once every 100 ms (typical EventSource reconnect rate). Combined with SSE's built-in auto-reconnect (exponential backoff on some browsers), this nets a maximum of one error toast per network drop instead of a hundred.
• **stopPolling resets the flag**: When stopPolling tears down EventSource, it also zeroes `streamErrorShown.value = false` alongside the existing `prevUnreadIds` and `hasFetchedInitial` clear, so a brand-new startPolling call later starts with a clean slate and the first real error _will_ show.
